先统一认知

重新认识 Codex：它不是替你乱写代码

Codex 更像一个能执行任务的 AI 程序员——能在本地目录里读、改、运行代码。你给它的不是一句「帮我做个产品」，而是一份清楚的任务说明书。

❌ 不会有结果的说法

  • 「帮我做个能赚钱的产品」
  • 「做个牛逼的网站」
  • 「随便整一个工具」

太模糊，AI 只能瞎猜。

✅ 能落地的说法

  • 讲清楚目标用户 / 痛点
  • 讲清楚输入 / 输出
  • 给出文档、约束、流程要求

把它当一份任务说明书来写。

⚠️ 底线：只做正向业务产品，不做灰色自动化。

第 ① 步 · 找需求

需求是「找」出来的，不是「想」出来的

新手最大的坑：坐在房间里凭空想一个「我觉得有人需要」的功能。真需求长在别人已经在搜、在抱怨、在付费的地方。

🔎 去有人抱怨的地方

真实的痛点会被反复说出来 —— 评论、issue、提问区。

💰 去有人付费的地方

已经有人在为它花钱，说明需求被验证过，不是伪需求。

📈 去有趋势的地方

看什么在涨、什么是新风口，踩在趋势上更容易起量。

下一页：4 个我常用的「找需求」地方。

第 ① 步 · 找需求

找市场和用户需求的 4 个地方

🐙 GitHub

看全球开发者在做什么：Trending 榜、热门 repo、issues 里的真实抱怨和「求一个能…的工具」。

擅长挖 技术型 / 工具型 需求

📰 自己的 RSS 订阅分析

把你长期关注的信息流喂给 AI 做分析，找出反复出现的高频话题和痛点 —— 你最懂的领域里的需求。

擅长挖 你最熟领域 的需求

🪙 生财有术官网

国内变现项目库，看别人已经在赚钱的项目和打法 —— 需求是否能变现，这里有现成答案。

擅长找 已验证能变现 的需求

🚀 ProductHunt

全球新产品每日首发，看老外在做什么、什么产品被疯狂点赞 —— 趋势和出海方向。

擅长找 趋势型 / 出海型 需求
第 ② 步 · 选定想法

今天的案例：AI 选题变现评估器

从这些渠道里，我们选定一个能落地的想法：用户输入一个内容选题，系统输出一份「选题评估报告」，帮他判断值不值得做、怎么优化、怎么变现。

👤 给谁用

做公众号、小红书、短视频、知识付费的内容创作者 —— 有很多选题，但不知道该写哪个。

🎯 解决什么

哪个选题更容易涨粉、更容易转化？标题和钩子怎么改更有传播力？

🧩 产品形态

左侧输入（人群/标题/大纲/变现方式），右侧一键生成评估报告。简洁、好演示。

第 ② 步 · 拆 MVP

动手前先回答 5 个问题

1
给谁用？
做自媒体但不会判断选题价值的人。
2
解决什么痛点？
不知道选题值不值得写、标题怎么改、怎么变现。
3
输入是什么？
目标人群、选题标题、内容大纲、变现方向。
4
输出是什么？
评分、痛点、标题建议、内容结构、变现路径、行动清单。
5
怎么变现？
免费单次评估 → 付费批量评分与优化 → 帮个人 IP 做选题库 → 给机构做内容获客工作台。
第 ③~⑤ 步 · Codex 实操演示

一个想法，如何用 Codex 走完这 6 个阶段

1
立项
把想法（含截图）丢给 Codex → 生成 PRD 放进 doc/ → git 初始化。
2
设计
按 PRD 设计高大上 UI → Codex 生成可看的 demo 原型页面。
3
开发
用计划模式 + 任务拆分 + TDD 按原型开发，计划存 doc、用 todo 跟踪。
4
测试调试
启停脚本、日志、prompt 配置化；调试中临时需求写补充 PRD、bug 记录成档。
5
复盘
版本定为 v1.0，复盘 bug 与新需求，提取可复用模板，建 wiki 索引。
6
上线
建 GitHub 仓库 → 写中英双语 README（带截图）→ 关联并推送。

STEP 4查阅计划后执行

prompt

实操提示词 · 阶段 4

测试与调试

STEP 5补充测试要求

prompt
配置文件我已设好，接下来做测试：
1. 创建启动/停止脚本，启动时检查端口
   是否占用，占用就 kill 掉重启。
2. 设 logs 文件夹按日期存日志，在关键点
   打日志（三方模型输入输出、前后端交互）。
3. 提示词 prompt 单独提取为配置文件，
   打上注释，方便我修改。

STEP 6调试中增加需求

prompt
从现在起增加规则：临时需求写入新的
PRD 作为补充需求；查到的 bug 在 doc 下
新建 bug 文档记录。本次增加：
1. 每个输入项支持自定义设置。
2. 未做的功能，点击后提示
   "该功能暂未开通，请耐心等待"。
实操提示词 · 阶段 5~6

复盘与上线部署

STEP 7整理复盘

prompt
项目开发完成，帮我整理 doc 文件：
1. 本次需求统一命名 v1.0；首版 PRD 之后
   提出的需求，作为增补加到 PRD 之后。
2. 创建 v1.0 复盘文件，复盘所有 bug 和
   后续需求，总结经验并给出后续建议。
3. 提取可复用代码模板，建文档标注
   可用场景和使用方法。
4. 创建 wiki，索引 v1.0 所有文档路径。

STEP 8版本管理与部署
